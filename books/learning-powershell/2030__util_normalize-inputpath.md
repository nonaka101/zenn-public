## 本処理の目的

対話形式で処理を進めるスクリプトを含め、ユーザーが入力した（あるいは用意した）パス情報を何かしらの処理に使うということは、PowerShell において それなりに遭遇するケースだと思います。

しかし、ユーザーが入力（用意）したパス文字列というのは、必ずしも**こちらが想定しているものとは限りません**。

本項では（ある程度の）**入力のブレに耐えられるように、パスの正規化を行う関数を作成します**。

## 入力されるパスについて

ここではユーザーに対し「（何かしらの）パスを入力してください」と入力を受け付ける場面を想定します。

この際、実際は様々な場面を想定しなければなりません。

### 設計者の想定から外れるパス入力の例

例えば `C:\Temp` というフォルダパスを入力してほしいという場面を想定しましょう。

`‪C:\Temp` という文字列は、フォルダプロパティ（下図）からコピペしてきたものになります。一見問題ないように見えますが、**よく調べてみると空白文字 `[U+202A]` が頭に入っている**ことが確認できます。

:::message

`‪C:\Temp` を VSCode などにペーストしてみると、`[U+202A]C:\Temp` と表示されると思います。

:::

![フォルダプロパティ画面](/images/books/learning-powershell/folder-01.png)

他にも GUI 上で右クリックした際に表示される「パスのコピー」からパスを取得してくるケースもあるかもしれません。この場合、`C:\Temp` は `"C:\Temp"` となります。

![右クリックから「パスのコピー」を選択](/images/books/learning-powershell/folder-02.png)

## サンプル：入力パスの正規化

上記の例から、様々な場面を想定して入力パスに正規化をかけてみます。

```ps1
function Normalize-InputPath {
  <#
  .SYNOPSIS
    入力されたパス文字列を正規化します。

  .DESCRIPTION
    入力されたパスの前後にある空白と外側の引用符を除去します。
    また、Bidi 制御文字、ゼロ幅スペース、BOM などの不可視文字を除去し、
    全角の円記号をバックスラッシュへ変換します。

    ドライブのルートを表すパス（例: C:\）を除き、末尾にある
    バックスラッシュまたはスラッシュも除去します。

  .PARAMETER InputPath
    正規化するパス文字列を指定します。

  .OUTPUTS
    System.String
    正規化されたパス文字列を返します。

  .EXAMPLE
    Normalize-InputPath -InputPath '  "C:\Work\Files\"  '

    前後の空白と引用符、および末尾のバックスラッシュを除去し、
    C:\Work\Files を返します。
  #>
  [CmdletBinding() ]
  param (
    [Parameter(Mandatory)]
    [string]$InputPath
  )
  $p = $InputPath.Trim()

  # 外側のクォート除去( "..." / '...' )
  $p = $p.Trim('"', "'")
  #不可視文字を除去（Bidi / ZWSP / BOM など）
  $p = $p -replace '[\u200B-\u200F\u202A-\u202E\u2066-\u2069\uFEFF]', ''
  # 全角￥ → \ (必要な環境向け)
  $p = $p.Replace('￥', '\')

  #末尾区切りの除去 (ただし "C:\" は維持)
  if ($p -notmatch '^[A-Za-z]:\\$') {
    $p = $p.TrimEnd('\','/')
  }

  return $p
}
```
